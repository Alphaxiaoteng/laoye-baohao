**副标题：跟着故事，走进潮汕文化**  
版本：V1.0｜日期：2026-11-05｜状态：待团队确认的开发需求基线  
交付：面向公众的响应式网页应用与可现场实测的比赛 Demo。
> 一句话介绍：用故事、轻互动和随时可问的 AI，帮助第一次接触潮汕的人，快速认识英歌、工夫茶、美食与民俗。

0. 文档边界与决策记录
本文是产品设计，不代表功能已经完成、资料已经授权或模型效果已经验证。所有工期、性能、内容量均为规划目标，需实测。
0.1 已确认
- 名称：老爷保号；副标题：跟着故事，走进潮汕文化。
- 核心目的：帮助用户快速了解潮汕文化，不做旅游预订、路线规划或求签产品。
- 主要内容：英歌舞、工夫茶、潮汕美食及制作食谱、营老爷与游神知识。
- 方言：独立音频播放功能，不做识别、跟读评分、实时合成。
- AI：全站悬浮窗口，点击打开，理解当前页面与本次会话上下文；不使用“阿潮”名称，不设置 AI 人物。
- 需有完整参考链接，支持开发借鉴；不直接复制未授权的网页、影像或音频。
- 本文不提供代码。
0.2 本版建议，待确认
- “一夜巡境”为故事入口；同时允许自由浏览，不强制按顺序学习。
- 潮剧与工艺为扩展展区；手记为最终成果，不做排行榜。
- 界面采用米白、砖红、墨绿及真实素材，不用数字人或泛国潮装饰。
- 首版约 10 分钟完成主要内容的入门体验；不是“十分钟全面读懂潮汕”的效果承诺。
0.3 撤回与纠偏
- 不用泡茶速度、温度等动作推断人格或规划旅程：无充分文化依据，也与当前目标无关。
- 不生成运势、神谕、平安保证；不把营老爷包装为算命。
- 不宣称所有英歌、茶艺、菜品都是游神仪式固定环节。
- 不写“摸老爷就会好运”等未经审慎核验的参与建议。
- 不把一次搜索未发现同类当作原创证明。
- 不把预置图文包装为实时 AI 输出，不把按钮切换包装为真实定位。
- 不宣称已阅读 wenjian.asia 所有页面：此前仅获取部分首页文本，子页仍待逐项核验。
1. 产品概述
1.1 产品定义
一座可以跟着故事逛、动手体验、随时提问的潮汕文化互动馆。故事帮助建立文化联系，图文影像提供事实，轻互动帮助理解，悬浮 AI 负责按需解释，独立音频提供入门听读。
建议宣传语：**看一场英歌，冲一泡茶，认识一个不止于标签的潮汕。**
1.2 用户与需求假设
| 用户 | 需求假设 | 产品回应 |
|---|---|---|
| 首次接触潮汕的公众 | 不知道从哪里开始，百科阅读门槛高 | 故事导览、短内容、即时解释 |
| 计划旅行的人 | 出发前理解看到的民俗与食物 | 入门文化内容，不提供实时营业承诺 |
| 学生与亲子家庭 | 希望可看、可玩、可问 | 轻互动、释义、音频、简短回顾 |
| 潮汕后裔或文化爱好者 | 想系统认识熟悉符号背后的知识 | 地区标注、来源、自由浏览 |
| 文旅与文化机构 | 需要可分享的数字体验样片 | 可配置内容与部署样例，合作价值待访谈验证 |
上述为产品假设，不是已完成的用户调研结果。
1.3 目标与非目标
目标：低门槛开始；能完成一条体验；能在关键页面问出并得到可信答案；认识地方差异；生成自己的文化手记。
非目标：全量潮汕百科、景区导航、票务、支付、算命、语音训练、社交社区、专业英歌动作教学、完整菜谱平台。
1.4 价值与创新边界
创新假设不是“功能更多”，而是将故事线、具体文化操作、跨模块解释和个人回顾结合。必须通过实测证明用户能理解文化联系，不能仅以聊天入口、音频播放或模块数量宣称技术创新。
2. 范围与优先级
| 优先级 | 范围 | 最小验收 |
|---|---|---|
| P0 | 首页、故事入口、自由浏览 | 两种入口都可完整走通 |
| P0 | 英歌、工夫茶、美食、营老爷 | 每模块至少一条完整体验，资料有出处 |
| P0 | 听潮独立页面 | 至少一组授权基础词句音频，点击播放 |
| P0 | 悬浮 AI 问答 | 当前页面上下文、引用、拒绝无依据问题 |
| P0 | 完成状态与文化手记 | 汇总真实体验，不伪造用户经历 |
| P0 | 无登录公网体验、加载与错误状态 | 未登录可用；失败可继续浏览 |
| P1 | 潮剧与工艺 | 一组经核验的关联内容 |
| P1 | 英歌鼓点或阵形互动增强 | 桌面触屏可用，有说明 |
| P1 | 食谱计时、手记图片下载 | 状态稳定，导出失败不丢内容 |
| P2 | 摄像头手势、多语言、多主题故事 | 不进入首版验收范围 |
若素材未授权，宁可缩小条目数，不使用来源不明的媒体。用户要求的独立音频功能不再降为纯愿景。
3. 信息架构与导航
3.1 一级结构
- 首页。
- 跟故事走：序章 → 英歌 → 茶 → 美食 → 巡境终章；潮剧工艺可为支线。
- 文化馆：英歌舞／工夫茶／潮汕美食／营老爷·游神／潮剧与工艺（可选）。
- 听潮：基础方言音频。
- 我的手记。
- 关于与资料来源、隐私说明、反馈。
- 全站悬浮“问一问”，不占一级导航页。
3.2 导航规则
桌面使用简洁顶部导航；移动端使用短导航或菜单，避免挤满图标。悬浮按钮不得遮挡下一步、音频、食谱按钮和系统安全区。
任何详情页都能返回所属模块；返回后保留滚动位置与已选条目。深链接直接打开时，不要求先走序章。
4. 核心用户流程
4.1 故事体验
打开首页 → 选择“跟故事走” → 简短序章与虚构说明 → 英歌体验 → 茶体验 → 美食体验 → 营老爷知识 → 完成回顾 → 手记。
可以跳过某站、返回补看，手记如实显示“已体验／未体验”。不以答错或未听音频阻止继续。
4.2 自由浏览
打开文化馆 → 选择模块 → 看内容／轻互动 → 点击问一问 → 获取解释与来源 → 关闭窗口继续 → 添加到手记。
4.3 音频
打开听潮 → 按类别选词句 → 点播放 → 听完停止／再次点击重播。无录音权限请求、无评分、无自动合成。
4.4 食谱
选菜 → 查看用料、过敏提示与器具 → 进入步骤 → 翻页／计时 → 查看完成提示 → 返回文化故事。展馆内浏览步骤不等于真的做菜，手记必须写“了解制作”，不能写“亲手完成”。
5. 页面级需求
5.1 首页
内容：名称、副标题、一句产品介绍、主视觉、主按钮“跟故事走”、次入口“自由逛逛”，听潮为可发现独立入口。
首次无需登录，不弹权限框。不要自动播放视频和音频。下方可用四张清晰文化入口卡，不强制将首页限制成只有一个按钮。
5.2 故事页
内容：章节名、短叙事、文化场景、一个主要动作、进度、继续／返回／跳过。
故事为原创虚构串联，事实卡片单独标注来源。明确说明“本故事不对应某地完整仪式流程”。不虚构神明发言，不让用户执行危险仪式。
5.3 模块首页
结构：一句入门解释 → 推荐入门条目 → 互动入口 → 相关内容 → 来源。每页默认先展示短内容，细节点击展开。
5.4 来源页
按模块列标题、发布机构、链接、访问日期、适用地区、核验状态。媒体另列作者、许可、取得方式。无法确定来源状态的条目不进入正式体验。
5.5 手记页
展示体验模块、收藏内容、用户输入、知识回顾、来源入口；可选配图。未上传照片则使用授权封面或无图版，不伪造现场照片。
支持文本预览；P1 支持图片下载，失败提供复制文本。公开分享前让用户预览并主动确认，不自动上传个人手记。
6. 英歌舞模块
6.1 功能
- 看英歌：可授权的短视频或图文，配文字说明与字幕。
- 识角色：卡片展示名称、形象、基本说明及地区差异。
- 看阵形：用自绘简图展示一组已核验的示例，标明来源，不强定“全潮汕统一阵形”。
- 听节奏：可选播放授权锣鼓片段。
- 轻互动：点击节拍或切换阵形，反馈为“完成体验”，不冒充专业动作评价。
6.2 状态
媒体加载中／可播放／暂停／加载失败；互动未开始／进行中／完成／重来。失败时保留图文与下一站入口。
6.3 参考与限制
参考站：http://www.wenjian.asia/ 。已获取的部分首页说明包含影像、阵形互动、智能导览等方向；所有子页面、素材许可和具体交互仍需开发前人工审阅，禁止声称已核验整站。
开发前页面盘点表字段：页面标题、URL、入口、内容类型、交互、可借鉴点、素材权属、我们做与不做、核验日期。
差异应体现为故事关联、页面感知问答与回顾，不是照抄外观或抓取全站内容。
7. 工夫茶模块
规范名称使用“工夫茶”；界面可解释常见写法，但不展开无依据的文字争论。
7.1 内容与操作
茶具卡 → 一组经核验的冲泡示例 → 分步演示 → 斟茶轻互动 → 文化释义。每步包含动作、原因、图示与继续按钮。
拖动为可选，点击始终可完成。对“关公巡城”“韩信点兵”等说法先找可靠资料与本地审核，不直接写成人人必须遵循的唯一标准。
7.2 验收
不靠摄像头也能结束；小屏可操作；动作完成后说明实际文化含义；不把演示手法自动转为专业教学认证。
7.3 参考
官方文化资料：https://www.ihchina.cn/project_details/15247/
TeaDemo：https://github.com/ZefanLin159/TeaDemo 。搜索摘要指向潮汕工夫茶手势 Demo，但此前抓取失败；许可证、运行效果、依赖和维护状态均待确认。
手势工具候选：https://github.com/abouchedidxcode/open-source-hands 。已获取部分仓库说明，可作为浏览器手势方案候选；许可证与子资源须实际读取 LICENSE 后确认，不沿用此前未经核验的许可结论。
8. 潮汕美食与食谱 GUI
8.1 内容层级
美食列表 → 菜品详情 → 制作步骤。首版建议若干简介条目与一道完整食谱；菜名及数量待团队核验决定，不默认所有地方都有相同做法。
8.2 菜品详情
菜名、代表图、短介绍、关联地区、用料、份量、器具、准备时间／制作时间估计、难度、过敏原、处理安全提示、资料来源。无可靠数据不填精确营养值。
8.3 制作 GUI
- 顶部：菜名、步骤数、返回概览。
- 主区：当前步骤图片、短动作说明、所需食材。
- 底部：上一步、下一步、可选计时按钮。
- 辅助：查看全部步骤、问一问“这一步为什么这样做”。
- 计时为提示，不自动代表食物已熟；浏览器后台限制与刷新后恢复需测试。
- 不用“时间到了即可安全食用”替代火候、熟度与温度说明。
8.4 安全与边界
不优先选生腌等高食品安全风险菜品作为跟做示范。不向过敏用户承诺替代食材绝对安全。调整份量时优先人工核验，不让模型自由改关键制作比例。

https://github.com/Anirudh77715/ai-agent-for-voice-cooking-assistant
两者此前仅检索到功能描述，可参考逐步烹饪交互；未完成代码运行与许可审查，不承诺可直接复用。
9. 营老爷·游神模块
9.1 内容目标
让用户了解称呼、巡境含义、活动中的人、社区关系与地方差异。民间信仰以“民间认为／祈愿”表述，不宣称超自然效果。
9.2 知识结构
| 主题 | 展示重点 | 审核要求 |
|---|---|---|
| 称呼 | 营老爷、游神等用语 | 不把所有称呼完全等同 |
| 巡境 | 社区巡游与平安祈愿 | 区分文化说明和事实断言 |
| 队伍 | 标旗、仪仗、神轿、鼓乐等示例 | 不强加所有地方必有英歌 |
| 时间 | 按具体地方与年份说明 | 不把旧活动日期当最新日程 |
| 地方差异 | 选择有来源的案例对照 | 地名、主体与年份不可省略 |
| 社区参与 | 居民协作、亲友往来 | 避免猎奇化与刻板印象 |
| 观礼提示 | 尊重现场安排，不妨碍队伍 | 不编通用禁忌或摸神像建议 |
9.3 交互
知识卡、队伍示意、地区案例切换；终章回顾见闻。故事中不规定用户替神明传话、不参与危险抬轿或穿越火堆操作，不做运势签。

10. 听潮：独立基础音频功能
10.1 定义
只做基础潮汕话词句的点击播放。独立页面、独立入口；不要求融入故事每一站，也不强制用户学习。
10.2 首版界面
建议分类：打招呼、喝茶吃饭、日常礼貌、文化词语。每条卡片含中文词句、普通话释义、可选拼音、口音标签、播放按钮、来源。
词句建议量：6—12 条，最终以授权与人工校对为准。显示顺序手工配置，不引入推荐算法。
10.3 播放规则
点播放一次；播放中按钮切换为停止；再次点击停止。开始新一条时停止上一条；切换页面停止。失败显示“暂时无法播放，请重试”，不重复自动请求。
不做进度条、倍速、录音、跟读、评分、识别、合成、打卡。拼音未经校对可先不显示，不能为了凑字段随意生成。

11. 潮剧与工艺（P1）
内容建议：一段入门说明、一组脸谱或角色示例、一组与潮绣／嵌瓷／木雕的关联说明。先选择有可靠资料、授权图片的内容，不为覆盖门类强行收录。
交互：点击对照、局部放大、相关内容跳转；无须三维建模或复杂拼图。

12. 悬浮 AI / Agent 需求
12.1 产品角色
全站文化解释助手，无人物姓名，无神明人格，无独立 AI 展馆。只有用户点击才展开；主内容不依赖 AI 才能阅读。
12.2 布局
桌面侧栏，移动端底部抽屉；支持关闭、清空会话、查看来源、查看相关内容。关闭仅收起，清空需确认。关闭时恢复焦点，不遮挡当前操作。
12.3 上下文范围
自动包含当前模块、条目、步骤和本次明确的交互状态；结合本次对话记录。不会上传整个浏览器历史、未授权个人资料或无关页面全文。
页面变化后更新上下文，并在窗口顶部显示“正在了解：工夫茶／斟茶”等可见标签。用户问“这个”时优先当前对象，歧义时先澄清。
12.4 能力
| 能力 | 例子 | 预期行为 |
|---|---|---|
| 当前内容解释 | 这个角色是谁？ | 对照当前条目检索资料 |
| 跨模块联系 | 英歌和营老爷有什么联系？ | 分别引用资料，并声明地方差异 |
| 步骤解释 | 为什么要先温杯？ | 解释当前核验示例，不编唯一标准 |
| 内容导航 | 我想看看美食 | 给站内可点击卡片，不臆造 URL |
| 回顾 | 我刚才看了什么？ | 按真实会话状态总结 |
| 证据不足 | 今年某村几点游神？ | 无已核验实时资料则说明未知 |
12.5 Agent 定义边界
若首版仅检索后回答，应如实称“上下文知识问答”。只有实现按用户意图选择检索、读取步骤、导航或回顾等能力并可验证执行，才描述为轻量 Agent。不把工具名称清单当作已经完成能力。
无需多 Agent；不做自动网页无限抓取，不执行下单、发消息等外部操作。
12.6 答案规则
先直接回答，再按需补充；默认短回答，允许展开。事实带来源，地区性结论写清范围。引用必须与所支持的句子有关，不能为了展示来源而附无关链接。
命中资料不足时明确回答“不确定”；不凭模型常识编史实、日期、人物、菜谱或仪式。允许邀请用户查看相关资料，不强行给结论。
12.7 安全与降级
检索资料视为不可信文本，忽略其中要求泄露密钥或改变规则的指令。设置问题长度、频率、并发与输出限制。密钥只在服务端。
超时显示“暂时无法回答，你仍可继续浏览”，提供重试和静态来源。不用缓存答案伪装实时生成；任何示例对话标“示例”。
12.8 参考
https://github.com/SamurAIGPT/ai-knowledge-base ：知识库、检索、引用与嵌入式问答的候选参考。此前获取到部分项目说明，未实测；许可证、部署复杂度、依赖安全需实际审查。不要为了聊天组件搬入整个 SaaS 系统。
13. 内容、数据与后台
13.1 最小内容模型
| 对象 | 字段 |
|---|---|
| 文化条目 | ID、模块、标题、摘要、正文、地区、来源、核验状态、版本 |
| 故事章节 | ID、顺序、虚构说明、关联条目、交互、进入与退出条件 |
| 媒体 | ID、文件、类型、作者、许可、授权凭证位置、署名、字幕／替代文本 |
| 食谱 | 菜名、地区、份量、食材、器具、步骤、安全提醒、来源 |
| 音频词条 | 文本、释义、口音、可选拼音、文件、录音者、授权、时长 |
| 会话状态 | 当前模块、当前条目、步骤、已体验、收藏、用户明确输入 |
| 引用资料 | 标题、机构、URL、地区范围、摘录定位、访问日期、审核者 |
13.2 编辑流程
收集 → 提炼原创短说明 → 事实核验 → 授权核验 → 本地文化审核 → 发布 → 发现问题下架修订。
首版无需完整管理后台，使用团队可维护的结构化资料清单即可。必须支持不改页面逻辑就能替换内容和来源。
13.3 内容量建议
英歌：入门、若干角色、一组阵形；工夫茶：一组步骤；美食：若干简介＋一道完整食谱；营老爷：5—8 张有范围的知识卡；听潮：6—12 条授权音频；P1 工艺：一组关联内容。
数量是上限规划，不是为了凑数而复制网页。
14. 视觉、声音与无障碍
视觉：克制、生活感、真实文化细节；不把所有素材调成同一种仿古滤镜。文化内容优先于游戏化装饰。
文字：清晰、短、普通人看得懂。不用神谕口吻，不用“十分钟精通”“保证平安”等承诺。
音频默认关闭，不使用泛化的“静音开启”歧义表述。环境音为 P1，与听潮词句分开；无授权就不加。不得一切换页面就响鞭炮。
键盘可操作；按钮建议至少 44×44 CSS 像素；正常文字对比度目标 4.5:1；视频有字幕；音频有文字；不只用颜色传达状态；支持减少动态效果。
响应式目标：常见手机、平板、桌面及投影；320px 宽度不出现关键按钮被裁切。
15. 非功能与隐私要求
性能为测试目标，不承诺结果：主要文本尽早显示；媒体懒加载；AI 首次反馈目标约 3 秒内，完整回答独立统计。不能用加载动画掩盖模型长时间不可用。
浏览器：至少测试近期 Chrome、Edge、Safari 和移动端微信内置浏览器。音频格式、自动播放限制、图片导出与跨域需逐项测试。
默认匿名体验；首版不采集位置、联系人、麦克风或摄像头。手记优先本地保存，并提示清除浏览器数据可能丢失。
若对话发往第三方模型，在隐私说明中写明；不主动采集敏感个人信息。服务端日志去除密钥与敏感文本，留存期限与清理机制上线前确定。
外链安全打开，控制富文本输入与渲染，限制请求体、上传类型和频率；默认不支持照片上传，可减少隐私与实现负担。
16. 数据观察与用户验证
只采集必要匿名事件，不默认保存问题全文。
事件：首页开始、模式选择、模块进入／完成／跳过、音频播放成功／失败、问答请求／成功／超时、来源打开、手记预览／导出成功。
核心观察：从开始到完成比例、每模块停留、失败率、问答有依据比例、用户能否复述三项文化知识。各指标无历史基线，不编造 DAU、付费率、增长或获奖概率。
建议找 5—8 名非潮汕背景用户做形成性测试，另请本地文化审核者检查事实；样本只能发现问题，不能声称代表所有人。

| ID | 场景 | 通过标准 |

18. 比赛交付与演示
赛事信息依据此前上传的“赛事整理材料”，该文件包含历史对话与规则摘要，并非本轮直接读取七份官方原件。提交前以主办方最新公告复核。
整理材料列出的关键事项：可在线交互原型；公开体验入口；建议魔搭创空间；无痕未登录验收；密钥安全；披露赛前成果与赛期增量；11 月 7 日下午初筛；决赛 5 分钟展示＋3 分钟答辩。日期、提交入口、封板方式仍须主办方确认。
18.1 实现顺序
1. 当天：冻结范围，建立内容和授权表，先部署空壳入口。
2. 接着：完成英歌、茶、美食、游神静态闭环与听潮。
3. 再接：悬浮问答、状态与来源，完成手记。
4. 最后：多设备、弱网、未知问题与现场测试；冻结非必要功能。
18.2 路演建议
- 30 秒：谁需要这个产品、为什么不是百科或攻略。
- 90 秒：进入故事，完成一个真实文化互动。
- 60 秒：评委现场问当前页面与跨模块问题，展示引用和边界。
- 40 秒：独立听潮与食谱 GUI。
- 40 秒：手记与内容来源。
- 40 秒：实际完成内容、技术边界、验证结果与落地方向。
现场模式只为快速选择章节，不冒充定位或现场巡游。备用录屏用于解释故障，不宣称能替代比赛要求的实机演示。
18.3 提交包
公网 URL、备用浏览器设备、项目说明、演示 PPT、素材授权表、资料来源表、已知限制、测试结果、赛前／赛期增量说明。源码提交和许可按最终规则办理。
